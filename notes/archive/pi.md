# Pi

**这个项目是什么**：Pi 是一个用 TypeScript 写的开源 AI agent 工具包（GitHub 上 10.8 万 star，作者 earendil-works）。它不是一个单一的软件，而是一套"搭 AI agent 的积木"：里面有统一的 AI 模型接口、agent 运行时（负责调用工具、管理状态）、编码 agent 命令行工具（跟 codex、opencode 同类的"终端里的 AI 编程助手"），还有终端界面库、持久化运行时等组件。它的官方定位叫"harness"（套件/外壳），意思是"给你一套现成的骨架，你在上面搭自己的 agent"。项目还声明了一个很有意思的产品理念：**"你可以直接问 Pi 让它解释自己"**（文档读不懂？让 agent 自己讲）。

## 2026-09-21 学习记录

**当天版本**：commit `c7cdb46` —— "fix(coding-agent): reject bug reports offline"（修复：离线时拒绝提交 bug 报告）。今天是第一次学习 Pi，先把项目整体认识一遍。

### 今天学到了什么

**1. 背景：Pi 的"工具箱"里都有什么？**

Pi 是一个 monorepo（一个代码仓库里放多个软件包）项目，`packages/` 下分了 12 个包，核心的三件套是：

- **pi-ai**：**统一 LLM API**——用一套接口接多家大模型（OpenAI、Anthropic、Google……）。大白话：**你不用为每个模型厂商各学一套调用方法，Pi 把它们的接口翻译成一种**。想换模型？改一行配置就行。
- **pi-agent-core**：**agent 运行时**——负责"让 agent 跑起来"的引擎：调用工具（比如读写文件、执行命令）、管理对话状态、决定下一步做什么。
- **pi-coding-agent**：**编码 agent CLI**——一个在终端里运行的交互式 AI 编程助手，这就是跟 codex、opencode 正面竞争的产品。

旁边还有：**pi-tui**（终端界面库，特色是"差分渲染"，见下文）、**pi-durable**（持久化运行时：会话、任务、文档可以存下来继续）、**chord**（应用组合运行时：服务、复制状态、RPC、插件）。

这个布局跟 opencode 的 monorepo 思路很像（还记得 opencode 也是把核心、协议、CLI 拆成多个包、依赖单向流动吗？）。**一个大项目拆成多个小包，每个包各管一摊、可以单独复用**，是大型 TypeScript 项目的常见章法。

**2. 特色一：不内置权限系统——把"安全边界"整个交给容器**

这是 Pi 最鲜明的性格。README 里白纸黑字写着：

> Pi 不包含内置的权限系统（permission system）来限制文件系统、进程、网络或凭证的访问。默认情况下，它以启动它的那个用户和进程的权限运行。

**这个选择跟咱们之前学的另外几个 agent 形成鲜明对比**：

- dsh 有审批系统（危险命令要批准）、hermes 有审批（deny 名单）、openclaw 有"可信网关"（网关才可信，执行体不可信）——它们都把安全护栏**内置**在程序里；
- Pi 的选择是**默认不设护栏**，它明说"如果你需要更强的边界，就把 Pi 放进容器或沙箱里跑"，并提供了三种现成模式：Gondolin 扩展（把 Pi 本体和模型认证留在宿主机，把内置工具和命令路由进一个本地 Linux 微虚拟机）、纯 Docker（整个 Pi 跑在本地容器里）、OpenShell（跑在策略控制的沙箱里）。

这教给我一个很重要的思路：**"安全边界放哪"是一个设计取舍，没有标准答案**。有的项目选择"内圈"（程序自己层层设防，适合普通用户开箱即用），有的选择"外圈"（程序保持简单透明，把防护交给容器/系统，适合懂行的人自己搭边界）。**两种哲学各有道理——内置护栏省心但代码复杂，外置边界干净但要求使用者有安全意识。**

**3. 特色二：把依赖当代码来审查（供应链加固）**

Pi 对"依赖安全"的较真程度也值得学。**供应链攻击（supply chain attack）**大白话解释：很多软件的代码里大量使用别人写好的库（npm 包），如果某个库被坏人劫持、塞进恶意代码，所有用了它的软件都会遭殃——这就是"从供应链上游下毒"。Pi 在 README 里专门写了一节"供应链加固"，几条做法很扎实：

- **直接依赖精确钉版本**：装依赖时不允许"随便取一个兼容版本"，必须钉死到精确版本号（`save-exact=true`），内部自己的包才用范围版本。**版本不定死，等于给了上游偷偷改你的机会。**
- **锁文件是"权威"**：`package-lock.json`（记录每个依赖确切版本和来源的文件）被当作唯一真相；还设了 pre-commit 钩子，**意外改到锁文件就不让提交**（除非显式放行）。
- **定时自动查漏洞**：CI 里有一个定时任务定期跑 `npm audit`（npm 官方的漏洞扫描工具），像咱们的每日任务一样自动巡检。
- **安装脚本要过白名单**：很多 npm 包安装时会执行一段脚本（安装时干点私活，也是供应链攻击最常见的藏身处）。Pi 生成自己的依赖清单（shrinkwrap）时，**带生命周期脚本的依赖必须进白名单才放行**，新来的、没审查过的直接拦下。

**4. 这个项目教给我什么？**

- **"统一接口"是生态级的好设计**：把多家大模型的差异翻译成一套接口，用户换模型零成本——**好的抽象层，是把"差异"挡在背后，把"一致"留给使用者。**
- **安全哲学要选边站，还要讲明白**：Pi 不装内置权限系统，但它**在文档里把自己的选择、理由和替代方案写得清清楚楚**（默认权限是什么、要边界用哪三种模式）。**"不设防"不是不负责任，把取舍说清楚、把方案给全，才是负责任。**
- **供应链安全是"日常功夫"**：钉版本、锁文件、自动查漏洞、脚本白名单——每一条单独看都不起眼，合起来就是一道扎实的防线。**安全不是某个大动作，是一堆不显眼的小习惯。**

### 一句话收获

Pi 让我认识了一种"极简外圈"的 agent 设计：核心三件套（统一模型接口、agent 运行时、编码 CLI）把功能做扎实，安全边界整个交给容器化（不内置权限、文档写清三种沙箱方案），再用钉版本、锁文件、自动 audit、脚本白名单把供应链守得严严实实——**"内圈做减法，外圈做加法"，也是一种成熟的安全观。**
